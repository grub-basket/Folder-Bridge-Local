# Folder Bridge Local 0.1.1

First public release. Folder Bridge Local is a trimmed fork of [Folder Bridge](https://github.com/tescolopio/Obsidian_FolderBridge) 2.15.5-rc.5 (upstream commit `a6ac1e1`) that keeps only local folders, mapped drives and network shares, on desktop. It is built for Windows 10 and 11 and also runs on macOS and Linux.

The idea: keep the vault small and bring in only the folders your notes and Bases need, instead of making a whole department share the vault. Obsidian cannot exclude folders, so a vault that is an entire network share can be too slow to load.

## Changes from upstream Folder Bridge

### Removed
- WebDAV, S3/Backblaze B2 and SFTP backends, the credential store and SFTP host-key trust, with their dependencies (`webdav`, `@aws-sdk/client-s3`, `ssh2-sftp-client`) and `chokidar`. The bundle went from about 3.4 MB to about 130 KB.
- The localhost file server and `data:` URI image embedding.
- TOC config files, device IDs and per-device overrides, mobile support (`isDesktopOnly: true`), the onboarding modal, dry-run mode, the watcher-suppression API, explorer tooltip augmentation and expansion-state persistence, and bulk add.

### File access (`VirtualAdapter`)
- Every mounted path goes through `PathMapper`, which refuses `.` and `..` segments. The allowlist is enforced for `stat` and `list` too, not only reads and writes.
- `stat` reports the birth (created) time as `ctime`, like Obsidian's own adapter, so Bases `file.ctime` is correct.
- `rmdir` honours `recursive: false`, `remove` unlinks a single file, and `rename` and `copy` refuse to overwrite. Names Windows cannot store get a readable error.
- New files, folders, renames and deletes inside a mount are registered in Obsidian's file tree before the call returns. This replaces upstream's patches of `vault.create`/`createBinary`, and makes `createFolder()` and `copy()` return the new item.
- Renames emit Obsidian's `renamed` event for the item and each descendant, so open tabs follow the file and internal links update. Upstream turned a rename into delete + create.
- Images, PDFs and media use Obsidian's own `app://` resource URL recipe, including the network-share (UNC) form. `getFilePath` and `getFullRealPath` make "Open in default app" and "Show in system explorer" work without patching `app`.

### Indexing and change detection
- A single routine (`syncTree`) adds, updates and removes entries for the first scan, manual rescans, polling and watcher recovery. A folder that fails to list, or a file whose stat fails, is left alone: a network error is never treated as a deletion.
- One recursive `fs.watch` per mount replaces chokidar's per-folder watchers and startup re-walk. On Windows this uses one change-notification handle per mount. Mounts that cannot be watched fall back to periodic rescans, and polling waits for the previous scan to finish.
- The last-known file list of each mount is restored right before Obsidian's metadata cache starts, so unchanged notes are not re-read on every launch (measured: 3,003 reads → 0 for a 3,000-note mount). The list is stored in Obsidian's local app-data folder, not in the vault.
- Scans use a small shared worker pool, give up and mark the mount offline after repeated I/O errors, and cap folder depth at 64 (link loops).
- Stricter ignore rules and moving a mount inside the vault update Obsidian's tree in memory without touching the disk. Large removals yield to the UI.
- Case-only renames on Windows and macOS do not leave duplicate entries.

### Offline network drives
- Reachability checks time out after 5 seconds and never stack more than one call per path, so a dead share cannot use up Node's file-system threads and freeze Obsidian.
- While a mount is offline, its files stay listed but operations fail immediately. Mounts reconnect automatically. The status bar shows how many mounts are offline.

### Safety
- Deleted files and folders are moved into `.folderbridge-trash` at the top of the mount, on the same share. Nothing is copied into the vault and nothing goes to the system trash.
- Deleting a mount's own folder in Obsidian only unmounts it.
- A permanent folder delete is refused when the folder contains files Obsidian is not showing.
- Saving over a note that changed on disk since Obsidian last saw it keeps the other version as a "changed by someone else" copy in the trash folder first.
- Program and shortcut files (`.exe`, `.bat`, `.cmd`, `.lnk`, `.url`, `.ps1`, `.vbs`, `.js`, `.msi` and similar) and names starting with a dot are always hidden.
- Path checks account for how Windows resolves names (trailing dots and spaces, 8.3 short names, junctions). System folders, credential folders, relative paths and the vault's own folder cannot be mounted. Mounts loaded from settings are re-validated.
- Ignore patterns use a linear wildcard matcher. The upstream regular-expression version could hang on some patterns.

### Interface
- New add/edit dialog: folder picker, a reachability check that waits until typing pauses, vault-folder suggestions and an Advanced section. New settings tab. Example paths match the current operating system.
- Mount root folders get a small marker in the file explorer, using a cheap per-mount lookup.
- Ignore matching is case-insensitive on Windows and macOS.

### Project

- 67 unit tests (vitest) covering path mapping, security checks, ignore rules, tree sync, the adapter and the watcher.

## Known limits
- Not yet tested on Windows hardware or real SMB shares; the Windows-specific paths are covered by unit tests only. Linux is untested.
- Files cannot be moved between a mount and the rest of the vault; copy them instead.
