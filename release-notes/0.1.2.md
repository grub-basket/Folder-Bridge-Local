# Folder Bridge Local 0.1.2

Data-safety release for shared network drives, plus merging when two people save the same note.

## Deletes are always recoverable
- `remove()` and `rmdir(recursive)` on a mount now move the item to `.folderbridge-trash` on the share. Obsidian calls these when **Deleted files** is set to **Permanently delete**, and sync tools call them when they replay deletions; network shares have no Recycle Bin. An empty-folder `rmdir` stays a real `rmdir`.
- A folder is not moved to the trash when it contains files Obsidian is not showing (other file types on a "Notes only" mount, ignored or hidden entries).
- Dragging a mount's top folder in the file explorer is refused: Obsidian's link updater would rewrite links in shared notes. Move a mount with **Edit mount…** instead, which renames it in place.
- New **Unmount…** item in a mount folder's right-click menu.

## Saves cannot destroy a file
- Before a file is overwritten, its current version is copied to `.folderbridge-trash/.saving` and removed once the new content is fully written. If a save fails (dropped connection, full disk, permissions), the previous version stays there and the error says where. On shares that allow editing but not creating files, saving still works without the copy.
- Files Obsidian does not know yet are created with `wx`, so creating a note never replaces a file on the share. `exists()` answers "exists" when the drive cannot answer.
- Parent folders are only created for new files, so a save never recreates a folder a colleague moved.
- Text encoding: notes in UTF-16 or Windows-1252 ("ANSI") open normally but refuse to save, because saving would replace characters such as £, € and é. CRLF line endings and a UTF-8 byte-order mark are written back as they were.
- No false conflict copies right after startup, before a mount finished its scan.

## Editing together
- When a note changed on the drive since Obsidian last saw it, the save does a three-way merge against the version Obsidian last loaded. Changes to different lines are combined, the merged text is saved, and the open editor reloads it. Only when both sides changed the same lines is the other version kept as "… (changed by someone else …)" in `.folderbridge-trash`.
- New setting **When a note changed on the drive while you edit it**: merge (default), keep their version as a copy, or save mine and discard theirs.
- Uses `node-diff3` (MIT) for the merge.

## Obsidian Sync guard
- While Obsidian Sync is on, a mount is only activated when its vault folder is in Sync's excluded folders, so shared files are not uploaded and deletions from other devices are not replayed onto the share.

## Other
- The "Markdown only" filter now includes `.base` files and is called **Notes only (Markdown, canvas, Bases)**.
- README: optimized for Windows and Windows network drives; editing together; deletes; encodings; Sync; risks the plugin cannot guard against.
- 80 unit tests.

## Known limits
- Not yet tested on Windows hardware or real SMB shares; Linux is untested. The Sync guard is untested.
