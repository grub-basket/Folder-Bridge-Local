# Folder Bridge Local 0.4.0

"Suggest mounts from Bases" finds the folders your Bases use and mounts just those. Mounts also now tell you when their rules refuse a file another plugin tried to save.

## Suggest mounts from Bases (`ddcb263`)
- **Where to find it:** the command **Suggest mounts from Bases**, or the **Suggest from Bases** button next to **Add mount** in the settings.
- **Where it looks for Bases:**
  - **This vault** reads `.base` files, plus ```` ```base ```` blocks inside notes. Only notes whose cached metadata shows a code block are read.
  - **A folder on disk (your old vault)** walks the folder for `.base` files using folder listings only. An optional **Also look inside notes** setting reads every note for embedded Bases. It's slower.
  - The disk walk skips hidden folders and the "Ignore in every mount" patterns, and never follows links. It lists a few folders at a time, shows progress, and can be stopped.
- **Share folder:** the folder that matches the vault root, for example `Z:\` or `\\server\share`.
  - A Base that filters on `Finance/Reports` is mounted from `<share folder>\Finance\Reports` at the vault folder `Finance/Reports`, so the Base keeps working unchanged.
  - The share folder is guessed from existing mounts whose real path ends in their vault folder. The last choice is remembered (`lastBaseScanSource`, `lastBaseScanRoot`).
- **Filters it understands:**
  - `file.inFolder("…")`, the early syntax `inFolder(file.file, "…")`, `file.folder == "…"`, `file.folder.startsWith("…")` / `file.path.startsWith("…")`, and `file.path == "…/note.md"` (the note's folder).
  - These are read in the top-level and per-view `filters`, through `and`, `or` and `not`. A folder under `not`, `!` or `!=` counts as left out; a double `not` counts as included.
  - Formulas, sorting and properties are ignored, because they never limit which notes a Base shows.
  - YAML that doesn't parse falls back to a scan of the raw text.
- **Results:**
  - **Suggested mounts** are listed A–Z. Each shows its path on the share, which Bases use it, and the subfolders it covers, with a size count on demand (stops at 50,000 items).
  - **Already in this vault** lists folders that are mounted or exist as local folders.
  - **Partly mounted** lists folders that already have a mount inside them.
  - Bases that only filter by tag or property, or by the note that embeds them (`this.file`), are listed separately to mount by hand.
  - Items that couldn't be read go in a collapsed list.
- **Adding:** **File types** and **Read-only** apply to the new mounts. **Add N mounts** uses the same checks as **Add mount**, and each row shows "Added" or the reason it couldn't be added.
- Searching never changes anything on the share.
- Parsing and suggestion logic is in `src/baseFolders.ts` and the disk walker is in `src/baseScan.ts`; both have unit tests. `browseForFolder` is now shared with the mount dialog.

## Fixes to the new dialog before release (`f8af9f6`)
- **Only confirmed folders can be added.** While their existence on the share is being checked, the button reads **Checking folders…**, so no mount is saved for a folder that isn't there.
- A check still running from an earlier scan can no longer unselect rows in a newer scan.
- A subfolder of a folder that can't be mounted whole (a local vault folder, or one with a mount inside) stays its own suggestion instead of being hidden.
- **Stop** shows what was found so far immediately, even if a call to an unresponsive share hasn't returned yet. **Back**, a new scan, or closing the dialog stops size counts.
- The disk walk no longer waits on timers. Obsidian slows timers in a background window, which would have stalled a scan left running there.

## Notice when a mount's rules refuse a save (`19c8ad9`)
- When a mount's **Ignore** or **File types** rules refuse a save, a notice now appears once per mount and reason, naming the file, the mount and how to allow it.
  - Saves from other plugins used to fail silently. For example, Edit History's `.edtz` files on a "Notes only" mount meant no edit history and no warning.
  - Program files get their own wording, since they are never saved to a mount.
- The save is still refused exactly as before. Reads of hidden files stay quiet. Editing the mount resets the notice.
- Applies to saving, appending, creating folders (Ignore rules only) and the destination of a copy.

## Known limits
- Not yet tested on Windows hardware or real SMB shares; Linux is untested. The Obsidian Sync guard is untested.
- Bases that choose notes by tag or property can't point to a folder; mount those folders by hand.
