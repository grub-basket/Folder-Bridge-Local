# Folder Bridge Local 0.5.0

The first release tested on Windows itself, against a real SMB share as both `\\server\share` and a mapped drive letter. It adds an optional fast scan for network drives and fixes six problems that only showed up there.

## Fast scan on Windows (`3cb6238`, `c5986fd`, `1afce98`)
- **New setting:** **Fast scan on Windows (uses PowerShell)**, off by default and shown only on Windows.
- **What it saves:** every launch re-checks each mount. Normally that means one request to the drive per file (Node lists names only, then asks for each file's size and dates), so 20,000 files on a network drive cost 20,000 round trips. A Windows folder listing already includes size and dates. With the setting on, one read-only PowerShell process asks for whole folders instead: one request per folder.
- **How it works:**
  - Up to 3 helpers run side by side, matching the 3 folders a scan lists at once. Extra helpers start only when needed.
  - The helpers only list folders; they never write anything.
  - Their results go through exactly the same rules as the normal scan: ignore patterns, hidden dot-names, program files, file types and links.
  - Dates are converted exactly like Node's own, to the millisecond, so switching the setting never makes notes look changed.
- **Safety:** if a helper fails, sends something unreadable, or doesn't answer within 10 seconds, it is stopped and that folder is scanned the normal way. The helper then rests for 30 seconds. A failure never looks like an empty folder. Turning the setting off or closing Obsidian stops every helper.
- **Watcher bursts:** changes noticed while Obsidian runs are now checked 6 at a time instead of one by one. With fast scan on, a folder that receives many files at once (a copy or unzip) is listed once instead of checked file by file.
- **Measured** on a share on the same PC, which has almost no network latency, so a real network should gain more (see `TODO.md`):
  - 3,731 items in 372 folders: normal scan 470–540 ms, fast scan 180–195 ms.
  - 20,040 files in 40 folders: 2.7–3.0 s, against 1.3 s with a single helper.
  - Scanning one way and rescanning the other found 0 changed notes every time.

## Fixes found by testing on Windows
- **Obsidian Sync blocked every mount in a new vault** (`47d8ec3`). Sync is on by default in new vaults even when it isn't connected to anything. Mounts are now refused only when Sync is actually connected to a remote vault and the folder isn't excluded.
- **Images and PDFs didn't load from `\\localhost\…` mounts** (`0875811`). URLs drop "localhost" as a host, so the file was looked for on the local disk. Shares on other server names were fine.
- **"Open in default app" did nothing for files on a share** (`dd37069`). After its permission prompt, Obsidian turns the file's address into a path by dropping `file://`, so `file://server/share/x` became the relative path `server\share\x` and nothing opened. Mounted files on a share are now handed over in the form Obsidian turns into `\\server\share\x`; its own prompts still apply. Drive-letter mounts and vault files are unchanged. Checked with an image and a PDF on Obsidian 1.14.4.
- **Moving an open note into a new folder in File Explorer closed its tab** (`c584a5c`). The move is now recognized and the tab follows the note. Moves into existing folders and renames already worked.
- **Links inside mapped-drive mounts were hidden** (`8f944cd`). A junction or symlink under `Y:\…` resolves to `\\server\share\…`, which didn't match the mount's own path. Both forms now show the same files.
- **The test suite now passes on Windows** (`97a62ab`). 4 tests assumed macOS paths.
